# v0.1 验收记录

## 交付范围

v0.1 完成 `Provider -> CLI -> Studio` 的最小可用闭环：

1. Provider 使用 Go + SQLite 持久化共识和共识图。
2. CLI 使用 Rust 创建、查看、更新、确认和废弃共识。
3. Studio 使用 Flutter 读取 Provider 并展示、编辑共识追溯图。
4. 共识图支持节点、关系和节点位置的持久化。

v0.1 不包含以下能力：

- 从飞书私聊自动导入消息；
- AI 从消息中抽取共识；
- 从共识生成 Memo；
- 面向公网用户的登录、权限和限流。

这些能力进入 v0.2 及后续版本。

## 验收命令

在 `apps/qtcloud-connect` 目录执行：

```powershell
pwsh -NoProfile -File tests/verify-v0.1.ps1
```

脚本会使用临时 SQLite 数据库和临时端口，不修改仓库数据，也不会发布包或创建远端 Release。

## 质量门禁

```powershell
cd src/provider
go test ./...
go vet ./...
go build ./cmd/server

cd ../cli
cargo fmt --check
cargo test --locked
cargo clippy --locked -- -A warnings

cd ../studio
flutter analyze
flutter test
flutter build web --release --base-href /
```

## 验收标准

- [x] Provider 健康检查返回 `{"status":"ok"}`。
- [x] CLI 创建的共识可以在 Provider 列表中读取。
- [x] CLI 可以确认共识，状态变为 `confirmed`。
- [x] 共识可以加入共识图并重新读取。
- [x] Studio 可以构建并连接同一个 Provider。
- [x] 新克隆的根仓库可以复现应用子模块指针对应的代码。

以上项目已在 2026-08-30 的本地验收中通过。根仓库随后提交了当前应用子模块指针，
因此可以从根仓库复现本验收对应的应用提交。

## 部署边界

v0.1 Provider 默认不启用认证。私有联调可以配置 `CONNECT_AUTH_TOKEN`；公网部署必须放在用户级认证、HTTPS 和限流网关之后。Studio 不能将 Provider 服务令牌编译进浏览器。
