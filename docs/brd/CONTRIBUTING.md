# BRD 维护指南

业务需求文档（BRD）描述业务场景中的问题。

## 写作原则

### 围绕场景组织

围绕业务场景组织文档，而非围绕「问题-方案」结构。每个场景包含：

- 工作角色：涉及的工作角色及权责
- 问题：业务中遇到的具体困难
- 假设：如果存在这样一个平台，能够...

### 以问题为中心

描述业务问题，而非技术方案。回答「为什么存在这个困扰」，而非「产品要做什么功能」。

### 使用假设句式

每个场景结尾用「如果存在这样一个平台，能够...」引导方案思考。

## 文档结构

```
## 场景一：xxx

### 工作角色
- 角色：权责

### 问题
问题描述

### 假设
如果存在这样一个平台，能够...
```

## 写作规范

- 使用工作角色（如发起方、确认方），而非具体岗位
- 描述真实的业务困扰，画面感
- 用业务语言，非技术术语
- 不写预期价值，用假设句式代替

## 与其他文档的关系

BRD → PRD → IXD → ADD，QA 验证所有层。

先有 BRD 讲清楚业务问题，才有 PRD 定义产品方案。

## 提交前自检

- 是否围绕业务场景组织
- 是否以问题而非答案为中心
- 是否明确了工作角色和权责
- 是否用假设句式引导方案
