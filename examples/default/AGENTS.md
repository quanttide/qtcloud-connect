# AGENTS.md - 实验室工作指南

本文档为 Agent 在 `examples/default/` 实验室中工作提供指南。

## 实验室定位

`examples/default/` 是 qtcloud-connect 的**实验室目录**，用于存放实验性、原型性的项目和代码。这里是创新的试验场，允许快速迭代和探索新技术、新功能。

## 核心目录作用

### 1. `docs/` - 实验文档

**作用**：记录实验过程、设计思路、技术选型和实验结果。

**包含内容**：
- **实验设计文档**：实验目标、方案设计、技术路线
- **实验记录**：实验过程、遇到的问题、解决方案
- **实验报告**：实验结果、数据分析、结论总结
- **技术调研**：新技术调研、竞品分析、可行性验证

**使用场景**：
- 记录新功能的原型设计过程
- 分析技术方案的可行性
- 总结实验经验和教训
- 为正式开发提供参考依据

**文件命名规范**：
- `design-*.md` - 设计文档
- `record-*.md` - 实验记录
- `report-*.md` - 实验报告
- `research-*.md` - 技术调研

### 2. `examples/` - 实验示例

**作用**：存放实验性的代码示例、原型项目和概念验证代码。

**包含内容**：
- **原型项目**：功能原型的完整实现
- **代码示例**：特定功能的示例代码
- **概念验证**：新技术或新方法的验证代码
- **工具脚本**：实验过程中使用的辅助工具

**使用场景**：
- 验证新功能的可行性
- 测试新技术栈的集成
- 创建可运行的原型演示
- 为正式开发提供代码参考

**目录组织**：
- 每个实验项目独立一个目录
- 包含完整的运行说明和依赖配置
- 提供清晰的演示流程

### 3. `src/` - 实验源码

**作用**：存放实验性的源代码，包括新功能的实现、重构尝试、性能优化等。

**包含内容**：
- **新功能实现**：正在开发中的新功能代码
- **重构代码**：架构重构或代码优化的实验
- **性能优化**：性能改进的实验性实现
- **技术集成**：新技术或第三方服务的集成代码

**使用场景**：
- 开发新功能的实验性实现
- 测试不同的架构设计方案
- 验证性能优化方案
- 集成新的技术栈或服务

**代码管理**：
- 使用特性分支进行开发
- 定期提交实验进展
- 记录重要的设计决策
- 保持代码的可读性和可维护性

## 实验工作流程

### 1. 实验准备
```
1. 明确实验目标和成功标准
2. 设计实验方案和技术路线
3. 准备实验环境和依赖
4. 创建实验文档和记录模板
```

### 2. 实验执行
```
1. 按照实验方案逐步实施
2. 详细记录实验过程和结果
3. 遇到问题及时分析和调整
4. 定期备份实验数据和代码
```

### 3. 实验总结
```
1. 分析实验结果和数据
2. 总结经验和教训
3. 评估实验目标的达成情况
4. 提出后续改进建议
```

### 4. 成果转化
```
1. 评估实验成果的价值
2. 决定是否纳入正式开发
3. 整理可复用的代码和文档
4. 更新相关技术文档
```

### 文档规范

- 保持文档的清晰和准确
- 使用统一的文档格式

### 版本控制
- 使用特性分支进行开发
- 定期提交实验进展
- 提交信息清晰描述变更
- 保持主分支的稳定性

### 测试要求
- 编写必要的测试用例
- 确保实验代码的基本质量
- 记录测试结果和问题
- 为正式开发提供测试参考

## 实验类型

### 1. 功能原型实验
- **目标**：验证新功能的可行性和用户体验
- **产出**：可运行的原型演示
- **文档**：功能设计文档、用户反馈记录

### 2. 技术调研实验
- **目标**：评估新技术或新工具的适用性
- **产出**：技术评估报告、示例代码
- **文档**：技术调研报告、对比分析

### 3. 性能优化实验
- **目标**：验证性能优化方案的效果
- **产出**：优化后的代码、性能测试报告
- **文档**：优化方案设计、性能对比数据

### 4. 架构重构实验
- **目标**：验证新架构设计的合理性
- **产出**：重构后的代码、架构文档
- **文档**：架构设计文档、重构记录
